# UniXNU 上游同步与缺口修补

## 上游范围

本轮将本机 UniXNU 主仓库从 `0fc0fc1` 快进到 `40d21cc`，保留本机 Pong 组件和 Darwin24 profile。新增提交修改设备记录、日志读取文档和设备同步脚本，没有新增 XNU 驱动补丁。

远端检查确认 Sheng `08cde20`、Adreno740 `5c8c145`、Ath12kWifi `f6bf561` 仍是各自已取得的最新 main。实际移植的是当前 Pong 尚未接入的上游实现，不把文档更新描述为新的驱动修复。

阅读并对照了上游中文 network、power、input、display、gpu、log-capture 文档及对应实现。没有读取手机或历史启动日志，没有安装、临时启动或上传改动。

## 本轮合并与修复

| 缺口 | 本轮处理 |
| --- | --- |
| GPU用户客户端仍扫描4096个对象；VM已有16384容量 | 移植Adreno740的句柄索引、空闲槽提示和常数时间存活计数；客户端上限引用VM的16384；保留Pong的16客户端、批量提交和各客户端地址范围 |
| GPU索引与分配失败生命周期 | 索引分配失败释放并清空入口；关闭时释放索引；隔离对象计入存活数；句柄回绕后拒绝新分配，避免复用旧身份 |
| 每次GPU提交读取两次未缓存映射用于诊断 | 对齐上游每64次提交取样；实际BO发布、屏障和Pong V500 TLB同步仍每次正常执行 |
| Wi-Fi发出wake但worker只IOSleep | 接通Sheng式MSI/TX事件等待：先检查、登记等待、再次检查，保留有界超时；唤醒后不无条件清零，避免丢失并发事件 |
| AudioReach读取完成缺少offset | 合并上游READ_DONE_V2偏移字段解析；短旧响应偏移为0；不因此发布未实现的录音端点 |
| DSP断开后仍可能消费旧音频响应并提交命令 | 通道断开时清队列、撤销ready和播放请求；命令及时退出；WRITE_DONE必须匹配当前映射handle，断开后不重新投递 |
| 构建记录固定使用旧上游revision | 构建入口记录实际上游HEAD和脏工作树状态；迁移基线更新到本轮同步版本 |

GPU共享索引源文件与上游一致，原有native4K批量映射、512页阈值TLB失效和同属性别名优化已存在。没有覆盖这些现有修补。

## 仍未实现或不能直接移植的部分

| 上游能力 | Pong边界与处理 |
| --- | --- |
| A740提交时省略TLBIALL、卡顿时kick/drain恢复 | Pong的V500路径和A730停顿恢复尚未组成同一套实现，本轮保留原同步，不能只删除TLB操作 |
| A740上下文接口与新提交结构 | Pong已有匹配22H374前端的批量ABI和context切换；整文件覆盖会破坏用户态协议，采用局部合并 |
| WCN7850已验证扫描、WPA2、DHCP | Pong是QCA6490/ath11k，不适用上游PCI ID、PHY、SID、固件和电源表；本轮事件修补不能证明实际链路或扫描成功 |
| SM8550录音/SoundWire | Pong尚未实现WCD938x输入链路；不移植Sheng的GPIO108、CS35L43和secondary I2S路由；继续使用Pong TFA9873/tertiary MI2S |
| DSP断开后自动恢复播放 | 本轮只使服务失效并停止新提交，未实现DSP重启后重新认证、映射和重开graph；DMA保留到真实静止或复位 |
| 完整平台休眠/唤醒 | 仍需各DMA、外设、中断和固件所有权的完整恢复；未增加占位成功返回 |
| DPU直接扫描输出 | Sheng为双管线与特定显示SMMU交接；Pong当前保留实际GOP/GPU复制路径 |
| 固件二维码/持久化日志读取 | 新文档将recovery列为正式读取方案；本轮只读规范，没有执行读取器或改动手机存储 |

## 构建

完整格式2 Darwin24 内核已编译并链接通过，使用上游`40d21cc`。首次编译发现Darwin24导出头未声明`clear_wait`，已按现有ADSP使用的真实XNU接口声明修正。最终编译日志为`build-20261028T060528Z.log`。

没有运行测试、基准、镜像哈希或设备回读；没有新实机功能结论。主机构建结果另存忽略目录`out/ipados18/services76-upstream-audit.json`。
